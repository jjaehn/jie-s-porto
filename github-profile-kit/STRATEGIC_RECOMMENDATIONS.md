## ✍️ 3. Recommended Commit Message Conventions

To give recruiters the impression of an industry-ready engineer who works seamlessly in agile teams, follow the **Conventional Commits** specification.

### Standard Format:
```text
<type>(<scope>): <short summary in imperative mood>

[optional body describing the motivation/rationale]
```

### Commit Types:
- `feat:` A new feature for the user (e.g., `feat(auth): add RFID verification handler`)
- `fix:` A bug fix (e.g., `fix(cv): resolve frame dropped issue in video stream`)
- `docs:` Documentation only changes (e.g., `docs(readme): add architecture diagram`)
- `style:` Code styling / formatting with no logic change (e.g., `style(tailwind): update card glassmorphism opacity`)
- `refactor:` Code change that neither fixes a bug nor adds a feature (e.g., `refactor(model): optimize CNN PyTorch data loader`)
- `test:` Adding missing tests or correcting existing tests
- `chore:` Updating build tasks, dependencies, gitignore, package configs
